# K9.Publish.CloudflareAssets

An application to publish a folder (a built static site) as a Cloudflare Worker's static assets, through Cloudflare's
[Direct Upload API](https://developers.cloudflare.com/workers/static-assets/direct-upload/). It needs no Node.js or
Wrangler.

- Only the files Cloudflare does not already have are uploaded: an unchanged folder uploads nothing.
- Each publish deploys the whole folder, so a file deleted from it is gone from the next version.
- The Worker is assets only, with no script. `_headers` and `_redirects` at the folder's root are sent as the assets'
  configuration, as Wrangler sends them, not served as files.
- When `TAG` is a number, a live version whose tag is a higher number is never replaced; the run ends successfully
  without deploying. Two publishes finishing out of order cannot put back the older one.
- Any failure exits non-zero, and the live version stays as it was. Every version stays in the Worker's Deployments
  tab, where a bad one rolls back.

The API token needs the account permission **Workers Scripts: Edit**. Give it through `CREDENTIALS` or the
`CLOUDFLARE_API_TOKEN` environment variable rather than `API-TOKEN`, which is echoed in the log with every other
argument.

## Arguments

| Argument             | Description                                                                                       | Required | Default                 |
|----------------------|---------------------------------------------------------------------------------------------------|----------|-------------------------|
| `SOURCE`             | The folder to publish; its contents become the Worker's assets.                                   | **YES**  |                         |
| `WORKER`             | The name of the Worker to deploy to.                                                              | **YES**  |                         |
| `ACCOUNT-ID`         | The Cloudflare account id.                                                                        | **YES**  | `CLOUDFLARE_ACCOUNT_ID` |
| `API-TOKEN`          | A Cloudflare API token with Workers Scripts: Edit. Shows in the log.                              | **OR**   | `CLOUDFLARE_API_TOKEN`  |
| `CREDENTIALS`        | Path to a file containing the API token, allowing for it not to show in logs.                     | **OR**   |                         |
| `TAG`                | Recorded on the version as `workers/tag`. When numeric, a live version with a higher tag is kept. |          |                         |
| `MESSAGE`            | Recorded on the version as `workers/message`.                                                     |          |                         |
| `HTML-HANDLING`      | `auto-trailing-slash`, `force-trailing-slash`, `drop-trailing-slash` or `none`.                   |          | Cloudflare's            |
| `NOT-FOUND-HANDLING` | `none`, `404-page` or `single-page-application`.                                                  |          | Cloudflare's            |
| `COMPATIBILITY-DATE` | The Worker's compatibility date (`yyyy-MM-dd`).                                                   |          | `2026-10-09`            |
| `DRY-RUN`            | Hash the files and, given credentials, list what Cloudflare is missing; upload and deploy nothing. |          |                         |

## Example

```
K9.Publish.CloudflareAssets.exe ---SOURCE=C:\Site\_site ---WORKER=my-docs ---TAG=1234 ---MESSAGE="CL 1234" ---HTML-HANDLING=none
```
