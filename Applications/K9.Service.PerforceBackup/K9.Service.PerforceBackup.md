# K9.Service.PerforceBackup

Keeps a Perforce workspace synced and archives a folder to a network share daily.

The service runs two jobs in one loop. Every `SyncSleep` seconds it syncs its workspace to `#head`, and
once a day at `BackupTimeOfDay` it compresses `BackupSourceFolder` into a single `.7z`, verifies it, copies
it to the NAS and prunes anything beyond `KeepCount`. Because both jobs live in the same loop the archive
can never run while a sync is in flight.

## Requirements

**7-Zip must be installed on the host.** The service looks for `7z.exe` on the `PATH` and then in the
standard `7-Zip` install folders, and refuses to start if it cannot find one — better than discovering it
at 3am. Set `SevenZipPath` to point at a specific binary.

## Arguments

| Argument   | Description                                                    | Required | Default |
|------------|----------------------------------------------------------------|----------|---------|
| _(first)_  | Path to the configuration file.                                | No       | `backup.json` beside the assembly |
| `DATA-DIR` | Override the `DataRoot` defined in the configuration file.     | No       |         |

## Flags

| Flag        | Description                                                                             |
|-------------|-------------------------------------------------------------------------------------------|
| `RUN-NOW`   | Run a backup immediately on the first cycle instead of waiting for the scheduled time.   |
| `NO-UPLOAD` | Create and verify the archive, but leave it in staging instead of copying it to the share. |

## Config Members

| Member                        | Description                                                                                                     | Default                          |
|-------------------------------|-------------------------------------------------------------------------------------------------------------------|----------------------------------|
| `DataRoot`                    | Path to where the Perforce workspace, staging folder and state file live.                                       | `D:\PerforceBackup\`             |
| `SyncSleep`                   | How often the workspace sync runs, in seconds.                                                                  | `300`                            |
| `LogFolder`                   | When set, a timestamped log file is written here alongside the console output.                                  |                                  |
| `PerforcePort`                | The Perforce connection string used to access your server.                                                      | `ssl:perforce.dotbunny.com:1666` |
| `PerforceUsername`            | The Perforce username to use when connecting.                                                                   |                                  |
| `PerforcePassword`            | The Perforce password to use when connecting.                                                                   |                                  |
| `PerforceClientName`          | The client name to give the workspace, will be suffixed with the machine name.                                  | `K9_PerforceBackup_Sync`         |
| `PerforceWorkspaceStreamName` | The name of the Stream to use. The client is created if it does not already exist.                              | `//NEXUS/Main`                   |
| `BackupTimeOfDay`             | The local 24-hour `HH:mm` time the daily backup runs at.                                                        | `03:00`                          |
| `BackupSourceFolder`          | Absolute path of the folder to archive. Wins over `BackupSourceRelativeRoot` when set.                          |                                  |
| `BackupSourceRelativeRoot`    | Folder to archive, relative to the workspace root. Empty archives the whole workspace.                          |                                  |
| `BackupName`                  | The stem used for archive names, and what pruning matches against.                                              | `Backup`                         |
| `BackupNameTemplate`          | Archive name template, supports `$Name`, `$Date`, `$Machine` and `$Changelist`. `.7z` is appended.              | `$Name_$Date`                    |
| `StagingRelativeRoot`         | Where the archive is built before being copied, relative to `DataRoot`.                                         | `staging`                        |
| `VerifyArchive`               | Run `7z t` against the archive before it is copied to the share.                                                | `true`                           |
| `RetryOnFailure`              | Retry a failed backup on the next cycle instead of waiting for tomorrow's window.                               | `true`                           |
| `MinimumFreeSpaceGigabytes`   | Refuse to start a backup with less than this much space free on the staging volume. `0` disables the check.     | `0`                              |
| `SevenZipPath`                | Explicit path to `7z.exe`, instead of searching for one.                                                        |                                  |
| `SevenZipArguments`           | Replaces the default compression switches.                                                                      | `-t7z -m0=lzma2 -mx=9 -mfb=64 -md=64m -ms=on -mmt=on` |
| `NetworkShare`                | The NAS share the archives are copied to.                                                                       | `\\192.168.20.21\Backups`        |
| `NetworkMapping`              | Drive letter to map the share to. Without one the UNC path is authenticated and used directly.                  |                                  |
| `NetworkUsername`             | Username used to reach the share when it is not already available.                                              |                                  |
| `NetworkPassword`             | Password used to reach the share when it is not already available.                                              |                                  |
| `NetworkCredentialsFile`      | A path to a file with two lines, first line being the username, second being the password. Overrides the two above. |                              |
| `NetworkTargetFolder`         | Subfolder on the share to write archives into.                                                                  |                                  |
| `KeepCount`                   | How many archives to keep on the share. `0` never prunes.                                                       | `7`                              |

## Example PerforceBackupConfig

```json
{
  "DataRoot": "D:\\PerforceBackup\\",
  "PerforceUsername": "my-username",
  "PerforcePassword": "my-password",
  "PerforceWorkspaceStreamName": "//NEXUS/Main",
  "BackupTimeOfDay": "03:00",
  "BackupSourceRelativeRoot": "NEXUS",
  "BackupName": "NEXUS",
  "BackupNameTemplate": "$Name_$Date_CL$Changelist",
  "NetworkShare": "\\\\192.168.20.21\\Backups",
  "NetworkTargetFolder": "NEXUS",
  "NetworkCredentialsFile": "D:\\PerforceBackup\\CREDENTIALS",
  "KeepCount": 7
}
```

## Safety Notes

- The archive is built in `staging` first, verified, and only then copied to the share. A network blip
  part-way through a multi-hour compression cannot corrupt the backup.
- The copy lands as `<name>.7z.part` and is renamed on the share only once the byte count matches, so an
  interrupted transfer is never mistaken for a good backup. Orphaned `.part` files are swept on the next run.
- If the share cannot be reached after the archive has been built, the verified archive stays in staging
  and the next attempt copies that file instead of compressing everything again. Staging is otherwise
  cleared at the start of every backup.
- The last successful run is recorded in `backup.state.json` under `DataRoot`, so restarting the service
  neither re-fires a backup that already ran today nor skips one that did not.
